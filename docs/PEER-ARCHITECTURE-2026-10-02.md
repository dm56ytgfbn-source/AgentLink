# AgentLink 多设备架构实施记录（2026-10-02）

目标是同一套 AgentLink 安装在每台 Mac/Windows 上；每台设备既能使用已配对设备，也能在本机用户允许后被其他设备使用。2 台到 4 台的基础场景不设主机角色。Agent 仍通过本机 MCP 接入，键鼠共享和视觉能力按平台单独声明。

## 已完成的基础层

- 节点按运行系统执行命令和启动应用；Mac 用 zsh / `open`，Windows 用现有 PowerShell / 启动器。节点只通告当前系统真正支持的能力，不把 Mac 伪装成 Windows 窗口节点。
- `/info` 提供稳定设备 ID、系统、能力和默认工作目录。Agent 会话选择目标后，默认目录从目标读取，路径按目标系统验证。
- Mac 与 Windows 都能作为远端：在隔离测试配置下，Windows 已实际连接 Mac 节点，完成认证、命令执行和文件写入。Mac→Windows 的现有链路保留。
- 发起配对时会建立本机持久身份；以后启用本机节点继续使用同一个 ID，避免一台电脑被识别成两个客户端。原有身份和凭据保持不变。
- 四个混合系统设备的注册、选择与两个 Agent 独立会话已有自动化测试。Mac 应用查询支持标准 Applications 目录。
- Mac 单窗口设置页已接入“允许其他设备使用这台电脑”、本机配对确认和停止接收。设置页打开时不会自动暴露局域网端口；隔离测试验证了启动、确认配对和停止后关闭端口。
- 两台设备若报告相同主机名，第二台按设备 ID 加上简短后缀，原配对不会被覆盖。
- 已在隔离路径打出 Mac 预览 App，并通过包内运行时、设置窗口、自带 Node 和签名校验；尚未替换用户当前安装的 App。

## 下一阶段：真正的“一台电脑一个 App”

1. 将 Mac 接收能力从源代码构建进正式 App，实机验证配对确认、关闭窗口后的生命周期、已授权设备查看与撤销。Windows App 采用相同语义。
2. 设备页显示所有已配对设备、在线状态、系统和可用能力；新增设备、选择 Agent 工作设备、键鼠共享目标都从同一设备列表选择。屏幕布局按设备 ID 保存，避免同名或改名串台。
3. 将键鼠共享的点对点连接扩展为设备图：每条边指定两个屏幕和方向，禁止重叠或歧义布局；在 Mac↔Mac、Windows↔Windows、Mac↔Windows 上分别做实机验证。
4. 完成跨平台后台启动、升级与恢复。安装更新不轮换设备 ID 或证书，升级前后验证双向操作和重连。
5. 建立内存、启动时间和空闲 CPU 基线，再做优化。测试至少覆盖 2/3/4 台、离线/重启/换 IP、多显示器、睡眠恢复和长任务；指标必须基于打包后的 App 实测。

## 当前边界

本阶段完成的是协议与执行核心、一次 Windows→Mac 实机验证，以及 Mac 设置页的接收端实现。预览 App 已生成并通过自动校验，但未安装替换当前版本、未通过真人界面验收，也没有发布给普通用户。Mac 节点目前不提供 Windows 式窗口捕获/输入。键鼠共享的 3–4 台拓扑尚未实现。不能把这些基础层测试当作全平台产品验收。

验证记录：Mac 与 Windows Node 构建通过；本轮新增的多设备、配对、接收端测试通过；完整测试 132 项中 131 项通过。唯一失败项是当前受限 macOS 环境不能通过 `security create-keychain` 建立测试钥匙串，该失败在本轮改动前也存在，仍需在正式签名/运行环境复测。Mac 预览包通过 `verify-release.mjs` 校验。实机 Windows→Mac 测试使用隔离配置，完成命令执行与文件写入，随后已停止临时 Mac 服务。
